# CrisisSim

### Интерактивный тренажёр антикризисного управления

Офлайн desktop-приложение для обучения и тестирования студентов IT-направлений в области управления кризисными ситуациями. Пользователь проходит пошаговые сценарии, принимает управленческие решения, анализирует последствия и получает разбор результатов с рекомендациями.

## О проекте

**CrisisSim** — интерактивный тренажёр антикризисного управления, предназначенный для моделирования кризисных ситуаций в IT-среде.

Главная задача программы — не просто выставить пользователю итоговый балл, а дать возможность пройти последовательность управленческих решений и получить первичную диагностику выбранного подхода:

```text
Кризисная ситуация
        ↓
Анализ исходных данных
        ↓
Выбор управленческого решения
        ↓
Обоснование своего выбора
        ↓
Следующий этап сценария
        ↓
Разбор ответов
        ↓
Сильные стороны и зоны улучшения
        ↓
Отчёт и история прохождения
```

Приложение работает локально и не требует подключения к интернету. Electron-клиент автоматически запускает локальный FastAPI backend, а пользовательские данные, тесты и история прохождений сохраняются в JSON-файлах на компьютере.

# Назначение

CrisisSim может использоваться:

- в учебных заведениях;
- на курсах повышения квалификации;
- при самостоятельной подготовке специалистов;
- на практических занятиях по управлению IT-проектами;
- для обсуждения управленческих решений на семинарах;
- для первичной диагностики логики принятия решений студентом.

Программа ориентирована на сценарный подход: студент работает не с изолированным теоретическим вопросом, а с описанием кризисной ситуации и последовательностью управленческих решений.

# Пример учебного сценария

В репозитории присутствуют стартовые сценарии.

Один из них моделирует ситуацию:

```text
Подозрительный трафик на сервере
        ↓
Диагностика инцидента
        ↓
Обнаружение DDoS-атаки
        ↓
Выбор мер реагирования
        ↓
Восстановление сервиса
        ↓
Post-incident review
```

Другой сценарий посвящён кадровому кризису:

```text
Уход ключевого разработчика
        ↓
Передача знаний
        ↓
Оценка bus factor
        ↓
Риски для релиза
        ↓
Управленческое решение
```

Таким образом система позволяет описывать не только технические инциденты, но и организационные, финансовые и проектные кризисы.

# Структура теста

Каждый тест хранится в JSON и содержит:

```text
ID
Тематику
Название
Описание кризисной ситуации
Итоговый положительный анализ
Рекомендации по улучшению
Набор вопросов
```

Каждый вопрос может включать:

```text
Текст вопроса
Тип ответа
Варианты решений
Затраты времени
Финансовые затраты
Подсказку
Признак правильного ответа
Пояснение
```

Поддерживаются два типа вопросов:

```text
single   — один вариант ответа
multiple — несколько вариантов ответа
```

---

# Модель ответа

Для каждого варианта решения могут задаваться не только правильность, но и дополнительные характеристики.

Например:

```json
{
  "text": "Включить защиту от DDoS у провайдера / CDN",
  "time_hours": 1,
  "cost_rub": 15000,
  "hint": "Наиболее эффективный способ фильтрации на уровне сети.",
  "is_correct": true
}
```

Это позволяет рассматривать ответ как управленческое решение с последствиями, а не как обычный вариант в тесте.

Главный экран агрегирует информацию о предыдущих прохождениях.

Отображаются:

| Метрика | Назначение |
|---|---|

| Последние сессии | краткая история недавней активности |

Данные рассчитываются backend-ом на основе сохранённых сессий.

# Прохождение теста

Тест проходит пошагово.

Для каждого вопроса пользователь видит:

- описание ситуации;
- текущий прогресс;
- один или несколько вариантов решений;
- связанные с ответом затраты времени и средств;
- подсказки;
- поле для собственного комментария.

Текстовое обоснование не является обязательным, но сохраняется вместе с сессией и попадает в итоговый отчёт.

Пользователь может вернуться к предыдущему вопросу и изменить ответ до завершения теста.

---

# Оценка результата

После завершения сессии ответы пользователя сравниваются с эталонными.

Для вопроса с одиночным выбором:

```text
Selected answer
      =
Correct answer
```

Для вопроса с множественным выбором правильным считается только точное совпадение множеств:

```text
Selected answer IDs
        =
Correct answer IDs
```

После этого вычисляется:

```text
correct_count
total_questions
correct_percent
```

Например:

```text
8 правильных из 10
        ↓
80 %
```

---

# Разбор результатов

После завершения теста пользователь получает детальный разбор.

Для каждого вопроса отображаются:

```text
Выбранный ответ
Правильный ответ
Ошибочные решения
Пояснение
Комментарий пользователя
```

Кроме покомпонентного разбора тест содержит итоговые блоки:

```text
Что сделано верно
Что стоит улучшить
```

Именно эти блоки позволяют использовать приложение не только для контроля знаний, но и для обсуждения управленческого мышления студента.

# История прохождений

Каждое завершение теста сохраняется как отдельная сессия.

Структура сессии:

```text
Session
│
├── session_id
├── test_id
├── topic_id
├── started_at
├── finished_at
└── answers[]
    ├── question_id
    ├── selected_answer_ids[]
    └── comment
```

Повторное прохождение того же теста создаёт новую сессию и не уничтожает предыдущий результат.

```bash
  --host 127.0.0.1 \
  --port 8000
```

```bash
curl http://127.0.0.1:8000/api/health
```

Pipeline:

# Безопасность и ограничения

Проект разработан прежде всего как локальный учебный тренажёр.

Текущая конфигурация:

```text
Backend bind: 127.0.0.1
Storage: local JSON
Internet dependency: отсутствует
Authentication model: local
```

В `backend/config.py` для демонстрационного административного режима используются статические локальные credentials.

Перед использованием вне учебной среды их следует заменить и не рассматривать текущую модель авторизации как production-ready security-механизм.

# Основная идея проекта

CrisisSim объединяет сценарное обучение и автоматизированный анализ действий пользователя.

```text
Theory
   │
   ▼
Crisis Scenario
   │
   ▼
Student Decision
   │
   ▼
Consequences / Resources
   │
   ▼
Next Decision
   │
   ▼
Result Analysis
   │
   ▼
Recommendations
   │
   ▼
History and Report
```

Вместо проверки только факта знания теоретического материала пользователь проходит последовательность связанных решений, приближенную к логике реальной кризисной ситуации.
